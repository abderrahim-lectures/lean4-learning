\chapter{Chapter 11: Quivers and path algebras}\label{sec:11-path-algebras:00-index:1}

\begin{learningobjectives}
\begin{itemize}
\tightlist
\item
  Encode a quiver as a \texttt{structure} of vertices/arrows/source/target.
\item
  Define \texttt{Path} as an inductive type indexed by its own endpoints.
\item
  Compose paths via \texttt{Path.append} and predict when composability side-conditions block a nonsensical composition.
\item
  Explain in what sense a path algebra \(kQ\) extends the \texttt{Ring}/\texttt{Module} machinery of Chapters 8 and 10.
\end{itemize}
\end{learningobjectives}


This chapter combines everything covered so far: inductive types (Chapter 1), structures (Chapter 2), and rings (Chapters 7--8), used to build a genuinely interesting example: the \textbf{path algebra} of a quiver.

Each section answers the question the previous one leaves open, working down toward a single target: the path algebra \(kQ\).

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  \textbf{What is the raw combinatorial object a path algebra is built from?} (\hyperref[sec:11-path-algebras:01-what-is-a-quiver:1]{Section 1}) A \textbf{quiver}: nothing more than a set of vertices, a set of arrows, and two functions recording each arrow's source and target --- a directed graph, stripped to the bare minimum.
\item
  \textbf{A single arrow is one directed step. What is a \emph{route} through several arrows, chained one after another?} (\hyperref[sec:11-path-algebras:02-paths:1]{Section 2}) A \textbf{path}: a sequence of arrows composable head-to-tail, together with, for each vertex, a length-\(0\) trivial path that starts and ends there and composes with nothing but itself.
\item
  \textbf{Both of the last two sections were stated on paper. How does the quiver definition become something Lean can check against?} (\hyperref[sec:11-path-algebras:03-defining-a-quiver:1]{Section 3}) A \texttt{structure} bundling the vertex type, the arrow type, and the two source/target functions --- a direct transcription, worked through on a small three-vertex example quiver used for the rest of the chapter.
\item
  \textbf{Given a Lean-encoded quiver, how is ``path'' encoded so that only genuinely composable arrow-sequences can be built at all?} (\hyperref[sec:11-path-algebras:04-paths-as-inductive-type:1]{Section 4}) \texttt{Path} as an inductive type \emph{indexed} by its own source and target vertex --- the dependent-type idea from Chapter 1, now put to real use: an arrow can only be \texttt{cons}ed onto a path when a proof shows its source matches where the path already ends, so a nonsensical composition is rejected before it is ever built, not caught afterward.
\item
  \textbf{Two paths, each already built, often need to be joined into one longer path rather than reconstructed by hand --- how?} (\hyperref[sec:11-path-algebras:05-path-composition:1]{Section 5}) \texttt{Path.append}, composition in the free category on \(Q\), defined by recursion and verified, by a genuine \texttt{rfl}, to agree with building the same composite path directly. This is also, once paths are given \(k\)-linear coefficients, the multiplication that makes the path algebra \(kQ\) a ring.
\item
  \textbf{Having built the definitions, what remains to actually practice with them?} (\hyperref[sec:11-path-algebras:06-exercises:1]{Section 6}, then the \hyperref[sec:11-path-algebras:07-checkpoint-project:1]{checkpoint project}) Exercises on the material above, followed by a project that adds one further piece of structure --- a path's length --- and proves, by induction mirroring \texttt{Path.append}'s own recursion, that composition respects it.
\end{enumerate}

By the end, ``quiver'' has gone from an unadorned directed graph to a category of paths with verified composition --- exactly the data a representation theorist needs before defining \(kQ\) itself, and exactly the bridge back to Chapter 10's \texttt{Module}/\texttt{LinearMap} machinery, since a representation of \(Q\) is precisely a module over \(kQ\).
