Every function type built so far, \texttt{Nat → Nat}, \texttt{Bool → Nat}, takes exactly one argument. What type, then, does \texttt{add : Nat → Nat → Nat} actually have? Reading the arrow as right-associative, it parses as \texttt{Nat → (Nat → Nat)}: a function taking one \texttt{Nat} and returning \emph{another function}, \texttt{Nat → Nat}. So \texttt{add 3 : Nat → Nat} is a genuine value, the ``add 3 to something'' function, before it is ever applied to a second argument. A ``two-argument function'' is nothing but a one-argument function whose result happens to be itself another function, applied one argument at a time. This pattern is called \textbf{currying}, and it is the type-theoretic form of the Hom-set isomorphism \(\mathrm{Hom}(A\times B, C)\cong\mathrm{Hom}(A,\mathrm{Hom}(B,C))\): a two-argument map is the same data as a one-argument map into a space of maps. The interesting part of this chapter is \texttt{structure}, which is how algebraic data will be packaged.

\section{\texorpdfstring{What forces \texttt{structure}}{What forces structure}}\label{sec:03-functions-and-structures:00-index:2}

A function takes its arguments one at a time, currying, as the section above just showed. That leaves open how several pieces of data belonging \emph{together}, like the \texttt{x} and \texttt{y} of a point, get treated as a single value instead of two arguments a caller must keep in sync by hand. \hyperref[sec:03-functions-and-structures:01-structure-basics:1]{Section 1} answers this: \texttt{structure} bundles named fields under one type, built with the anonymous constructor \texttt{⟨...⟩} and read back out by field projection \texttt{.field}. This is the packaging mechanism every algebraic object from Chapter 7 onward, a group, later a ring, is built from.

\texttt{Point} bundles two \texttt{Nat}s specifically. The same shape of bundling is needed for \emph{any} pair of types, not just \texttt{Nat} and \texttt{Nat}. \hyperref[sec:03-functions-and-structures:02-type-parameters:1]{Section 2} parameterizes a \texttt{structure} by a type, the same way \texttt{identity} in Chapter 1 was parameterized by \texttt{\{α : Type\}}. \texttt{Pair α β} is not one structure but a whole family of them, one per choice of \texttt{α} and \texttt{β}, exactly the shape \texttt{Group (G : Type)} will need later.

Some structures are not built from scratch; they are an existing structure plus one more piece. Re-declaring every inherited field by hand each time does not scale. \hyperref[sec:03-functions-and-structures:03-extending-structures:1]{Section 3} gives \texttt{extends}, which builds a new structure containing an old one whole, plus more, generating a forgetful \texttt{.toX} projection for free, the exact mechanism a \texttt{CommGroup} will use in Chapter 7 to add commutativity to \texttt{Group} without repeating the group axioms.

By the end of the chapter, \texttt{structure} is no longer just a convenient keyword for grouping fields. It is the bundling-and-forgetting machinery every algebraic structure in the rest of this book depends on.
