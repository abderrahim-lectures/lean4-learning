## v1.5.1 — Corrections from the 2026-08-03 closing review

A closing verification pass (`reviews/2026-08-03/`) re-triaged the previous
round's findings, audited the bibliography against the literature, swept the
manuscript programmatically for link and cross-reference defects, and — per
the project's adversarial-mathematics review protocol — re-derived the worked
examples by hand and tested the boundary and degenerate cases. This release
applies every finding from that pass.

### Mathematical and type-theoretic corrections

**Chapter 11, Section 2 — the trivial path was defined wrongly.** The text
said a length-$0$ path $e_i$ "composes with nothing but itself." That is
false: $e_i$ is the *identity* at $i$. The book's own Section 4 builds
`pathAlpha` by composing `Path.nil 0` with `alpha`, Section 5 states the
identity laws and sets one as an exercise, and the quoted
Assem–Simson–Skowroński source has $\sum_x \varepsilon_x$ as the unit of $KQ$
— all three contradict the sentence as it stood. Corrected in both
`02-paths.md` and the chapter index.

**Chapter 5, Section 3 — the Π-type universe rule omitted `imax`.** The rule
was printed as $\mathtt{Type}\,(\max(i,j))$. Lean's actual rule is
$\mathtt{Sort}\,(\mathrm{imax}(i,j))$, where $\mathrm{imax}(i,0) = 0$; the
$j = 0$ case is the impredicativity of `Prop` and is what makes `∀` land in
`Prop` at all. As printed, the rule put `∀ n : Nat, n ≥ 0` in `Type 1`,
contradicting every `∀`-statement in Chapters 3–11. The rule is now stated
over `Sort` with `imax`, with a paragraph on impredicativity and the two
`#check` outputs that distinguish the two rules. Section 2's informal `max`
statement now flags that it omits the `Prop` case.

**Chapter 5, Section 4 — the opening `rfl` block taught the inverse of the
truth.** The comment on `0 + 2 = 2` explained a different term (`2 + 0 = 2`);
the `2 + 0 = 2` line was commented out even though its own comment said it
succeeds — and it does succeed, verified against Lean 4.32.2. Neither example
could exhibit the asymmetry the comments asserted, because both are closed
terms and both reduce. Rewritten to use a variable `n`, which is the only way
the asymmetry appears: `n + 0 = n` is `rfl`, `0 + n = n` is not.

**Chapter 1, Section 5 — the Σ-type reading of `∧` described the `∨`
construction.** The "constant family, varying index" bullet ended by
describing a two-element index type, which is what the *next* bullet uses for
`∨`, collapsing the contrast the passage is built on. Restated correctly as
$P \wedge Q \cong \sum_{\_ : P} Q$.

**Chapter 3, Section 5 — "ex falso quodlibet" was attributed to classical
logic.** It is $\bot$-elimination, which the book's own Section 2 lists among
the rules accepted by *both* classical and intuitionistic logic, and the same
file closes by noting Lean's logic is intuitionistic. Corrected.

**Chapter 11, Section 5 — three composition orders in one section.** The
section fixes path order explicitly and warns that mixing orders is a common
source of confusion, then gave the $kQ$ multiplication in function order. The
formula is now in path order, matching `Path.append` and the quoted source,
with a parenthetical for readers coming from function-order texts.

### Clarity

**Chapter 1, Section 3 — `autoImplicit` is now named.** Section 2 teaches
`{α : Type}` carefully; Section 3 then relies on Lean's `autoImplicit` setting
to insert `{n : Nat}` and `{α : Type}` binders that nothing in the source
writes, without saying so. A paragraph now names the mechanism and gives the
explicit-binder form for Mathlib-style projects, which set
`autoImplicit := false`.

**Chapter 1, Section 4 — free monoid vs. free commutative monoid.** Section 1
calls $(\mathbb{N}, +, 0)$ the free *commutative* monoid on one generator;
Section 4 spells the claim out quantified over *every* monoid. Both are true
of $\mathbb{N}$, and a paragraph now says why — the free monoid on one
generator is already commutative — rather than leaving the adjective to appear
and vanish.

### Citations

- Gentzen's natural deduction dated **1935** in the body, matching the
  bibliography's `[Gentzen1935]`; Jaśkowski's independent 1934 system noted.
- CIC citation now gives the full venue (*COLOG-88*, LNCS 417, 1990) and the
  hyphenated surname **Paulin-Mohring**, with an explicit note distinguishing
  it from Pfenning & Paulin-Mohring 1989, with which it is easily conflated.

  independently verified" note; the source is paywalled and this remains open.

### Build pipeline

**`build_latex.py` did not run under pandoc 3.x.** `strip_hypertargets()`
matched only pandoc 2.x's `\hypertarget{s}{\section{…}}` shape, and only
`\section`/`\subsection`. Pandoc 3.1.3 emits `{%` and a newline before the
heading command and wraps `\chapter` the same way, so the regex matched
nothing and the run aborted on Chapter 14's `\chapter{}` assertion. The regex
now tolerates both forms.

**Build scripts moved to `lean_book_latex/build/`**, alongside the output they
generate rather than inside the Markdown source tree. Path construction in
`build_latex.py` updated accordingly, and references in `CONTRIBUTING.md`,
`lean_book/README.md` and `skills/latex-typesetting-reviewer/SKILL.md` follow.

**Added `lean_book_latex/build/build_pdf.sh`**, which runs the full chain
(`build_latex.py` → `xelatex` → `biber` → `xelatex` ×2) in one command, with a
`--latex-only` flag for contributors without a TeX installation.

**`.devcontainer/devcontainer.json` now installs Python, pandoc and TeX Live**
(`texlive-xetex`, `texlive-latex-extra`, `texlive-fonts-extra`,
`texlive-science`, `biber`, `latexmk`). The container image had been reduced
to bare Ubuntu, leaving the documented build pipeline unrunnable out of the
box.

### Front matter

"About this book" now describes this review round alongside the six-model
round it follows, including the fact that the closing reviewer recorded two of
its own predictions that testing disproved.

### Notes

- Every fix above landed in the Markdown source; `lean_book_latex/` was
  regenerated from it. No `.tex` file was hand-edited.

  cases behind the Chapter 5 §4 rewrite and the two `#check` outputs behind the

  import-free file blocks for minutes in page-in). The new `Vec` snippet in
  Chapter 1 §3 is therefore uncompiled, and its prose was written to claim only
  what the code says rather than what Lean does with it. **Re-run
  `lake build` in `lean_project/` before treating this release as
  compile-verified.**
- The fixes themselves have not had an adversarial re-review. The open items
