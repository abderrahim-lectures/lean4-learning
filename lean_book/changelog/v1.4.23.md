## v1.4.23 — Add dbg_trace tracing to Chapter 1 (PR E1, part 1)

Kicks off the dbg_trace initiative: every Lean code block in the book
will eventually get step-by-step tracing where genuine recursion exists,
shipped one chapter at a time. Chapter 1 is the pattern-setting
installment.

Surveyed all 28 Lean code blocks across `01-basics/`'s six files first.
Only three have real recursion to trace: `Vec.replicate`, `Vec.dot`
(recursing on two `Vec`s at once, accumulating a running total), and
`double` (recursion hidden inside `Nat.rec` rather than a visible
self-call). Each gets a `dbg_trace`-annotated sibling definition, so the
original stays untouched, with prose explaining what each printed line
means. `Vec.dot` also needed a genuine same-length worked example added,
since the book had previously only ever shown its type-error case.

A real limitation was found and documented rather than glossed over:
`myLength` (computed via `List.rec` under `#reduce`, since its code
generator can't compile `List.rec` directly) cannot be traced with
`dbg_trace` at all — verified empirically that kernel-level reduction
silently skips the trace's side effect entirely, unlike `#eval`.

Everything else in the chapter — simple `#check`/`#eval` one-liners,
non-recursive `def`s, and tactic-mode proofs — has no multi-step
computation to trace and was left unchanged.

All Lean snippets verified directly against the toolchain pinned in this
repository's `lean_project/lean-toolchain` (`v4.31.0`), run as one
cumulative script matching how each chapter's snippets actually
accumulate.
